# Техническое задание: Сервис управления профилями и заказами
## Часть 1. API-контракты и форматы обмена данными

### 1.1. Контекст и архитектурные ограничения
Сервис представляет собой REST-микросервис, обеспечивающий регистрацию пользователей и обработку клиентских заказов. Все входящие и исходящие данные передаются строго в формате `application/json`. 

Сервис должен гарантировать единообразную структуру ответов при возникновении ошибок валидации. В случае передачи некорректных данных система не должна возвращать дефолтные трассировки стека (stack trace) или стандартные ошибки веб-сервера.

### 1.2. Контракт эндпоинта регистрации (`POST /api/v1/auth/register`)

#### Входящий payload (JSON)
* `email` (string, обязательное) — адрес электронной почты пользователя.
* `age` (integer, обязательное) — полный возраст пользователя в годах.
* `password` (string, обязательное) — пароль для создания учетной записи.
* `role` (string, необязательное) — системная роль. По умолчанию присваивается `CUSTOMER`.

#### Ожидаемые ответы:
* **`201 Created`**: Пользователь успешно создан. 
  ```json
  {
    "status": "success",
    "data": {
      "user_id": 1042,
      "email": "user@example.com",
      "role": "CUSTOMER"
    }
  }
  ```
* **`400 Bad Request`**: Ошибка валидации входных параметров (подробные правила описаны в спецификации валидации).
* **`409 Conflict`**: Пользователь с таким `email` уже зарегистрирован в системе.

### 1.3. Контракт эндпоинта скидок (`POST /api/v1/orders/apply-discount`)

#### Входящий payload (JSON)
* `order_id` (integer, обязательное) — уникальный идентификатор заказа.
* `discount_percent` (float/integer, обязательное) — размер применяемой скидки в процентах.

#### Ожидаемые ответы:
* **`200 OK`**: Скидка успешно применена, возвращается итоговая сумма.
* **`400 Bad Request`**: Превышен допустимый размер скидки или некорректный статус заказа.
* **`403 Forbidden`**: У пользователя недостаточно прав для выполнения операции (подробности в спецификации безопасности).
